# 物品(治具・工具・計測器)持ち出し管理 — M5Stack Tab5 の設計 (ToolCheck)

## Context

置き場の物品を誰が持って行ったか分からず、見つからないときに探せない・返却漏れが起きる。
Tab5 + QR ユニット + ToF + 内蔵カメラで「持出/返却の登録」「貸出中の見える化」「無登録持ち出しの警告と撮影」を
工具箱の横に置いた 1 台で完結させる。電源断でも記録が残ること、返却履歴 100 件を見られることが要件。
誰が持って行ったかを画像で示せれば、次の利用者が気付き、ルールを守るよう促せる。
モバイルバッテリーで動かす場合もあるので、できるだけ省電力にする。**PoC。**

開発時の計画書を公開用に整えたもの。括弧内の日付はその仕様を決めた日。実装の経過と実機で分かったことは [開発記録](開発記録.md)、部品ごとの実測は [spikes/README.md](../spikes/README.md)。

## 決定事項 (2026-09-12)

- **利用者 ID の桁数は設定値** (既定 7 桁)
- **単体で設置し、USB 充電器 (またはモバイルバッテリー) で給電する。** PC 側の受け取りツールは作らない
- **省電力を優先する。** 使わない機能・電源は切る。CPU クロックを落とし、アイドル時はさらに省電力にする
- **物品番号は 2〜15 文字。** NVS のキー上限 (15 文字) にそのまま収め、貸出中の記録は物品番号をキーにする
- **いろいろな物を管理するので物品番号には幅を持たせる** (2〜15 文字の印字可能 ASCII)。
  **1 次元バーコード (JAN など) は扱わない** — 実物の JAN も読めなかったので仕様から外した (2026-09-13 決定)。物品には QR のラベルを貼る
- **名前は出さない。** 物品番号と利用者 ID だけ表示。マスタ無し
- **Wi-Fi は使わない。** 時刻は設定画面と USB シリアルで設定し RTC で保持
- **警告は 40 秒で警告 1 → 60 秒で警告 2 → 警告 2 から 2 分で音を止めて「無登録開放」を記録し、画面に赤帯を残す**
- **音量は 3 つとも設定可 (下限あり)**: 操作音・警告 1・警告 2。警告 2 ≧ 警告 1、警告は下限未満にできない。試し鳴らし付き
- **LCD は明るさを設定でき、無操作で減光・消灯する。** 開放・QR 読取・タッチで復帰、警告中は最大
- **写真**: 引き出しの開放を検知したら内蔵カメラで撮影する
  - **SD が刺さっていて設定が ON のときだけ SD に保存**し、ファイル名に時刻を入れる。**SD が無ければ自動で OFF**
  - 写真が **100 件を超えたら、アイドル時に古い画像から削除**
  - **登録せずに持って行った人の写真は、SD に保存しなくても画面に表示し続ける**。SD が無いときは電源が落ちたら消えてよい (内蔵フラッシュには残さない)
  - SD に写真が残っていれば、**履歴の行をタップして写真を見られる**
  - **カメラを使わない設定を持つ**。モニタはカメラが引き出しを開ける人を写せる画角に設置する
- **設定まわりは 1 つの設定画面に集約する** (⚙ 長押し + PIN)
- **採用した提案**: 付け替え (「持出に切替」) / 名札が先でも可 (20 秒) / 引き出しが閉じているとき名札だけで自分の貸出中一覧 /
  打ち切り時に持出を利用者「不明」で残す + 赤帯 / 物品番号の検索 / 警告の一時停止 / カメラを使わない設定
- **検証で問題なければ採用**: 未確認の無登録があるあいだは消灯せず減光で止める / ~~消灯中の手動ライトスリープ~~ (**2026-09-12 M2 で本体ごと止まって復帰しなかったので不採用**)
- **Unit ToF が無くても貸出管理ができるようにする (2026-09-14)。** 設定「引き出しセンサ」で使う / 使わないを切り替える
  (**既定は使う**。使う設定なのに見つからなければヘッダの ToF● を赤にする)。使わない設定では開閉を受け付けず、セッションは物品の QR で始まり、
  **写真は名札で確定したときに撮る** (名札を読まずに立ち去った打ち切りでは写真が残らない。無登録の開放は起きない)
- **SD の写真の全削除を設定画面に置く (2026-09-14)。** 「NVS データ削除」を「データ削除」にして 3 つ目のボタン (3 秒押し続け)。
  **消したことを開閉ログに 1 件残す** (後から追えるように)。USB シリアルは `sd erase photos YES`
- **カメラ・警告音 (ブザー)・操作音は既定でオフ (2026-09-14 夕)。** 設定画面で入れる (カメラの入切は再起動で反映)。
  既定値は保存された設定が無いときだけ効くので、実機は `cfg set` でそろえる
- **動作ログ (USB シリアルに出す動作の行の入切) は作らない (2026-09-14)。** 当初は既定 OFF の設定と `log on|off` を置く計画だった。
  M5 6 段目で PC が読んでいないときの出力は捨てるだけで止まらなくなり、切る理由が無くなった。ログは本体に残らず、PC を繋いで見るときは出したいので、常に出す。
  `Config::serial_log` は保存の形 ([15] bit3) を変えないために残す (どこからも読まない)
- **電源を入れてから初めて PC から開くと再起動する件 (`rst:0x17`) は困らない (2026-09-15)。** 対処しない
- **待機・減光・消灯でもスピーカーは止めない (2026-09-15)。** 入切のたびに始めるときの音が出るおそれがあり、止めても差は約 0.01A
- **Port A は Unit PaHub v2.1 で分ける (2026-09-15、Unit ToF の到着時)。** Tab5 の Port A が 1 口のため。挿す ch は決め打ちせず、起動時と抜き差しのたびに自動で探す (「挿すところが変わっても自動で検知できるのが理想」)
- I2C 配線は 1m 以内に収まるので読取エラー対策は今は考えない

## 調べた仕様の要点 (docs.m5stack.com / スイッチサイエンス / esp-bsp / ローカルのコア・ライブラリ実物)

**Tab5 (C145)**
- ESP32-P4 (RISC-V 2 コア 360MHz) / Flash 16MB / PSRAM 32MB
- 5 インチ IPS **720×1280** (縦がネイティブ)、静電タッチ。**2025-10-14 以降の出荷は ST7123**。手元の M5GFX 0.2.28 は対応済み
- 明るさ: `M5.Display.setBrightness(0〜255)`。パネルのスリープ: M5GFX `Panel_DSI::setSleep()`。**`Touch_ST7123::sleep()` は空実装**。実測ではパネルスリープ中はタッチが取れない (バックライト 0 だけなら取れる。2026-09-13)
- 音: ES8388 + NS4150B **1W スピーカー** (`M5.Speaker.tone()` / `setVolume(0〜255)` / `end()`)
- RTC: RX8130CE。**バックアップはスーパーキャパ (0.07F) だけ**。バッテリー NP-F550 は**別売**
- **Port A (HY2.0-4P) = G53 SDA / G54 SCL / 5V。** 5V は `M5.begin()` で既定 ON。出し分けは `ext_PA` (M5-Bus と共通) と `ext_USB` (USB-A)
- **M5Unified の Tab5 初期化は、無線モジュール ESP32-C6 の電源 (IO エキスパンダ 0x44 bit0 `WLAN_PWR_EN`) を ON にしている。** 充電 (bit7 `CHG_EN`) も ON
- M5Unified の `config` で `internal_imu` / `internal_mic` / `internal_spk` / `led_brightness` を切れる
- 電流計 INA226 あり (`M5.Power.getBatteryCurrent()`)。バッテリー側の電流なので、USB 給電だけのときに全体が読めるかは未確認
- **CPU 周波数**: `setCpuFrequencyMhz()` で P4 (rev<3) が受け付けるのは **360 / 40 / 20 MHz**。
  **Arduino のビルド済みライブラリは `CONFIG_PM_ENABLE` が無効** → 自動 DFS・自動ライトスリープは使えず、状態に応じて自分で切り替える。手動の `esp_light_sleep_start()` は使える
- USB-C は USB-Serial/JTAG 内蔵 (`USBMode=hwcdc` / `CDCOnBoot=cdc`)。動作温度 0〜40℃
- Arduino: FQBN **`esp32:esp32:m5stack_tab5`** (esp32 コア 3.3.11 に既にある)。`ChipVariant` は `prev3` (既定, P4 rev<3)。実機の rev で確定
- 既定パーティション `default_16MB`: **nvs は 0x5000 = 20KB しかない** / app 6.4MB×2 / spiffs 3.4MB
- 日本語フォントは M5GFX の **`lgfxJapanGothicP_8〜40`**

**カメラ (SC2356, MIPI-CSI)** — Arduino コア 3.3.11 に部品が同梱
- `ESP_Video` ライブラリ (例 `libraries/ESP_Video/examples/mipi_csi_camera`)、`esp_driver_jpeg` (ハードウェア JPEG エンコーダ)、`esp_cam_sensor`
- **SC2356 は esp_cam_sensor では SC202CS として扱う** (esp-bsp の m5stack_tab5 も "Supported camera sensors: SC202CS")。プリビルドで有効・MIPI 自動検出・既定 1280×720
- Tab5 の配線 (esp-bsp `m5stack_tab5.h`): **XCLK 不要・リセットピン無し・電源は IO エキスパンダ 0x43 の bit6**。**SCCB は内部 I2C を共有**。画像は **270° 回転**
- **Arduino の例は ESP32-P4-Function-EV-Board 向けのみ。Tab5 での実績は未確認**

**microSD** — **SPI 接続** (CS 42 / SCK 43 / MOSI 44 / MISO 39)。**カード検出ピンは無い**。FAT の長いファイル名は有効。M5GFX `drawJpgFile(fs, ...)` で縮小表示できる

**Unit QRCode (U173, STM32F030, I2C 0x21)** — QR を読む (1 次元バーコードは実物の JAN も読めず、扱わないことにした)。AUTO/MANUAL トリガ。
M5Stack Basic の別の機器で同じユニットを使ったときに踏んだ罠: **READY は 1 とは限らない → 0 以外なら必ず読み出す** / `setTriggerMode()` は void → 読み戻して検証 /
`0xFF`・`65535` は I2C 失敗 / 長さは 64 以内で読み捨てる / 固まったら `begin()` から再初期化。AUTO 中は同じコードを何度も読む。
**待機中の消費は QR ユニットが支配的** → その機器で使っていた間欠トリガ (1.4 秒周期 / 0.7 秒窓) を流用

**Unit ToF (U010, VL53L0X, I2C 0x29)** — 3〜200cm、±3%、**視野角 25° (固定)**。Pololu `VL53L0X` 1.3.1 (`startContinuous(period_ms)`)。
→ **2026-09-15 に届いたのは Unit ToF4M (U172, VL53L1CX = VL53L1X 系, I2C 0x29) だった** (型番のレジスタ 0x010F = 0xEACC で見分けた。Pololu VL53L0X の `init()` は 0xC0 が 0xEE でないので 0ms で失敗する)。
4〜400cm、視野 15〜27° (ROI で絞れる)。ドライバは Pololu `VL53L1X` 1.3.1 (M5 公式の M5Unit-ToF4M も中でこれを使う)。
本体ファームは距離モード Medium・測定時間 33ms、`dataReady()` を見てから `read(false)` で読む (待たない)。VL53L0X には対応していない
比較: **VL53L1X (Unit ToF4M) は ROI を最小の 4×4 SPAD に絞ると視野 約 15°**

**ホストのテスト環境** — g++ / clang / WSL / Docker は無い。**Visual Studio 18 Community の `cl.exe` (MSVC 14.51) はある**

## ハード構成

```
Tab5 Port A (G53/G54, 5V) ── Unit PaHub v2.1 (PCA9548AP, 0x70〜0x77) ─┬─ ch0 Unit QRCode (側面スイッチ=I2C, 0x21)  … 画面の横に固定
                                                                       └─ ch1 Unit ToF4M  (VL53L1X, 0x29)            … 工具箱の上端、床向き
Tab5 内蔵カメラ … 引き出しを開ける人が写る向きにモニタを設置
Tab5 microSD   … 任意 (刺さっているときだけ写真を保存)
給電: USB-C に USB 充電器 または モバイルバッテリー。NP-F550 は任意 (モバイルバッテリー運用では付けない — 充電に電力を取られる)
```
Port A の I2C は 100kHz。`Wire.begin(53, 54)` は `M5.begin()` の後。
ch の割り当ては 2026-09-15 に繋いだときのもの。**ファームは ch を決め打ちせず探す** (下の「Unit PaHub v2.1」)。

**Unit PaHub v2.1 (U040-B-V21, PCA9548AP)** — Port A を 6 ch (0〜5) に分ける I2C のスイッチ (2026-09-15 に調べた。docs.m5stack.com / M5Unit-HUB)
- アドレスは基板の DIP スイッチ 3 つで 0x70〜0x77 (既定 0x70)。対応表 (3・2・1 の順): LLL = 0x70 / LLH = 0x71 / … / HHH = 0x77。
  2026-09-15 の DIP は「全部 HIGH」。スイッチの ON が H か L かは図だけでは決まらないので、ファームは 0x70〜0x77 を全部探す。
  **実機ではこの DIP で 0x70 に応答した** (`#I2C hub=0x70 qr=ch0 tof=ch1`。ON = L 側とみる。決め打ちしなくてよかった)
- 制御は 1 バイトのレジスタだけ。**書くとビット n で ch n を繋ぐ** (複数を同時に繋げる・0 で全部切る)、読むと今の値。
  **電源を入れた直後と抜き差しの後は 0 (全部切れている) → ch を選ばないと向こうのユニットは見えない** (2026-09-15、PaHub を挟んだ実機で `qr=0`)
- M5 公式ライブラリ (M5Unit-HUB の `UnitPCA9548AP`) も `1 << ch` を 1 バイト書くだけ。M5UnitUnified 一式が要るので使わない
- QR (0x21) と ToF (0x29) はアドレスが違うので、**両方の ch を同時に繋いだままにする** (やりとりの度に切り替えない。QR と ToF のドライバは今までどおり Wire を直に使える)

## 動作仕様 (要件 + 採用した提案。★はまだ確認していない提案)

### QR の判別 (`code_classifier`)
- 前後の空白・CR/LF を除去。制御文字・空白・**カンマ**を含むものは不正 (CSV 出力で列がずれる)
- `^[0-9]{利用者桁数}$` → **利用者 ID**。それ以外で **2〜15 文字**の印字可能 ASCII → **物品番号** (読むのは QR だけ。13 桁の数字などを QR にしたものも物品番号として扱う)
- **利用者 ID に英字・記号も使う設定 (`user_id_alnum`、既定 false。2026-09-15)**: 少人数の現場では名前を英字にして記号で桁埋めした ID (`TANAKA_` など) を名札にできる。
  設定した文字数ちょうどで、物品番号と同じ使える文字なら利用者 ID とみなす (その文字数の物品番号は読めなくなる)。設定画面「利用者 ID・PIN」で切り替え
- **15 は NVS キーの上限なので設定でも超えられない。** 16 文字以上は「物品番号が長すぎます」と表示。大文字・小文字は中身どおり区別する

### セッション (`session`)
開放検知 **または** 最初の QR 読取でセッション開始。1 セッション = 1 人。

1. 物品 QR → 貸出中なら**その場で返却** (社員IDを読まず、返した人は記録しない。2026-09-15)。そうでなければ「**持出**」として名札待ちの保留リストに積む
   - 同じコードは、最後に読んでから 3 秒間読み捨て (AUTO スキャンの多重読取対策。読み続けている間は延び、コードごとに見る)
   - 1 回のセッションで扱った物品をもう一度読んでも行は増えず、持出と返却が入れ替わらない (名札待ちの行があれば警告のタイマは読み直す)。行は 20 件まで
   - 名札待ちの持出の行だけ ✕ で取り消せる。返却済みの行・名札待ちの切替の行は ✕ では消えない
   - **返し忘れの物品を次の人が持ち出す**: 返却済みの行に「**持出に切替**」ボタン。押すと名札待ちの「切替」になり (もう一度押すと返却に戻す。返却は書き直さない)、名札で確定した人に切替の印で新しく貸し出す。名札先の 20 秒で押すとその場で貸し出す (戻せない)
   - **取りやめ (2026-09-15)**: QR を読んで持って行くのをやめるとき、セッションごと 1 回押しの「取りやめ」ボタン (名札待ちの持出・切替があるか、開けて何も読んでいない間だけ出す)。名札待ちの持出は消し、名札待ちの切替は返却 (記録済み) に戻す。開けた後か済んだ返却があれば開閉ログに「取りやめ」で残す (赤帯にはしない・写真は残る)。QR だけで何も済んでいなければ何も残さない
   - **名札待ちの行 (持出・切替) が無い (返却だけの) セッションは警告しない。** 最後に進んでから 20 秒で「確定」として終える (返した人は記録しないので利用者は空)。
     **「返却完了」ボタンで 20 秒を待たずにすぐ終えられる** (2026-09-16: すぐ貸し出したいとき。取りやめと同じ場所に出す)
2. 名札 QR → **確定**。名札待ちの持出・切替をその人で記録する
   - 保留 0 件でも開放ログに ID を記録 (要件⑤ 何も持って行かない場合)
   - **名札が先でも可**: **名札を読んでから** 20 秒間に読んだ物品は同じ人で即確定 (2026-09-13 決定)。
     物品を読んでも延びない。同じ名札をもう一度読むとそこから 20 秒。別の人の名札か開放でそこまでを 1 回のセッションとして区切る。
     **「完了」ボタンで 20 秒を待たずにすぐ次の人を登録できる** (2026-09-16:「続けて物品を読めます」画面。取りやめ・返却完了と同じ場所)
   - **セッションが無いときに名札だけかざす** → **引き出しの開閉に関係なく**その人の貸出中一覧を表示 (開放ログには残さない。2026-09-13 決定)
   - 開閉ログの 1 件はセッションの終わり (名札先の 20 秒の後・打ち切り・次のセッションで区切ったとき) に書く。QR だけのセッションも書く (開放なしの印)
3. 警告 (「最後に進んだ時点」= 開放 or 有効な QR 読取 からの経過で判定。秒数は設定値)
   - **40 秒: 警告 1** (警告 1 の音量・断続・画面赤点滅) / **60 秒: 警告 2** (警告 2 の音量・連続)。同じ音量でも鳴らし方で段階が分かる
   - 開放だけ → 「QR を読ませてください」、保留あり → 「名札を読ませてください」。どの有効 QR でも音は止まり、タイマは読み直し
   - ★警告中のオーバーレイに、開放時に撮った写真を出す
   - **打ち切り: 警告 2 から 2 分で音を止めて未確定として処理** — 返却は確定 (返却者不明)、**持出は利用者「不明」で貸出中に載せる**、
     1 枚も読まなかった開放は「**無登録開放**」。**画面上部に赤帯と写真を残し、設定画面で確認して消す**
4. **未確認の無登録があるときは、セッションのオーバーレイにもその写真と時刻を小さく出す** (消灯から開放で起きた人でも目に入るように)
5. **警告の一時停止中**: 開放してもセッション・警告を起こさない (撮影はする)。**QR の登録はできるが、音と打ち切りは止め、停止が明けた時点から警告を数え直す** (2026-09-13 決定)。
   ヘッダに残り時間を常時表示し、開始・終了と停止中の開放を開閉ログに残す。時間で自動復帰
6. 確定後に開いたままの引き出しでは警告しない (閉→開で次の開放)。★開きっぱなし 3 分で「閉めてください」案内音

### 引き出し検知 (`drawer_detector` / `drawer_source`)
- 入力は `drawer_source` で差し替える: **ToF** (到着後) / **シリアル注入 `sim open|close`** (開発フラグ ON のとき)
- ToF: 測定間隔は電力状態で変える。設定画面の「ToF 校正」で全段閉めて基準距離の中央値を取り cfg に保存
- 開: 基準 − 開閾値 (初期 100mm、実測で決める) を N 回連続 / 閉: 基準 − 閉閾値 を 1 秒連続 (ヒステリシス)
- **登録後の押さえ (2026-09-16)**: 名札で確定した・セッションが終わった (確定・返却完了・取りやめ・打ち切り)・判定を再開した後は、
  距離が閉の範囲に **2 秒続けて戻るまで次の開放を作らない** (引き出しを開けたまま・作業者が前にいて反応したままのため。途中でまた反応したら数え直し)。
  開いたままなら「閉」は今までどおり 1 秒で出す。開放で次のセッションに区切ったときは押さえない。`#DRAWER hold` / `#DRAWER rearm`
- **設定画面を開いている間は開閉を判定しない (2026-09-16)**。ToF が反応してもセッション画面に移さず、開閉ログにも残さない。閉じた後は上の押さえから受け付ける
- ToF が見つからない・タイムアウト・範囲外が続く → 「**引き出しセンサ異常**」を画面に常時表示 (音は鳴らさない)。
- **引き出しセンサを使わない設定 (`drawer_sensor_enabled` = 0、2026-09-14)**: ToF を確かめず、開閉 (`sim open|close` も) を受け付けない。ヘッダに ToF● を出さない。
  使う設定では `hw/drawer_sensor` が距離を読む。ヘッダの ToF● は緑 / 黄 = 未校正 / 赤 = 見つからない・使えない値が続く

### 写真 (`camera` / `sd_card` / `photo_store`)
- **撮影**: カメラは普段は取り込みを止めておき、**開放を検知したら CPU を 360MHz に上げて取り込みを始め**、露出が落ち着いたフレームを 270° 回転 → ハードウェア JPEG → 取り込み停止。
  開放 1 回につき 1 枚。開放から撮影までの時間は実機で決める (設定値)。待機中にセンサ電源まで切るかは電流と遅れを実測して決める
- **引き出しセンサを使わない設定では、名札で確定したときに撮る (2026-09-14)**。行を記録する前に写真名を決め、持出・返却・名札先に読んだ物品・開閉ログで同じ写真名を使う。
  物品の QR・セッションの外の名札・同じ名札の読み直し・打ち切り (名札なし) では撮らない。待ち時間は同じ `capture_delay_ms` (設定画面の表示は「撮影までの待ち時間」)
- **M3 の実測 (2026-09-13、`spikes/README.md`)**: 取り込みを止めた状態から再開すると最初のフレームは 83ms、明るさは 2〜8 枚目 (約 150〜550ms) で落ち着く。
  センサの電源 (0x43 bit6) を切ってから入れ直すと、初期化を含めて最初のフレームまで 432ms。**カメラの状態 (閉じる / 初期化して停止 / 取り込み中 / bit6 OFF) で電流は変わらなかった** (0.42〜0.45A)。
  → **決定 (2026-09-13 決定): 待機中はセンサの電源を切らず、初期化したまま取り込みを止めておく** (電力は稼げず、撮影が約 350ms 遅れるだけなので)。
  「カメラを使わない設定」のときだけ電源を切ったまま初期化しない (上の項のとおり)。開放から撮影までの既定 (`capture_delay_ms` = 500) は、しゃがむ・横からの写りを見て M5 で決め直す
- カメラを閉じるときは、ISP のデバイス (`ESP_VIDEO_ISP1_DEVICE_NAME`) を閉じてから `video.end()` を呼ぶ (逆だと後始末に失敗する)。入切を繰り返してもヒープ・PSRAM は漏れない
- **写真名は開放を検知した時点の時刻で決める。** 撮った写真の保存と、そのセッションの記録 (貸出・返却・開閉ログ) で同じ名前を使う。
  1 回のセッションの中で開け直したときは、記録には最初の開放の写真名を使う (開け直しの写真も SD には保存する)
- **カメラを使わない設定**のときは、カメラの電源を切ったまま初期化もせず、撮影・写真表示・📷 を出さない。ToF 校正画面にいる間は撮らない
- 直近の開放の JPEG は PSRAM に持つ。**SD が無いときは電源が落ちたら消える**
- **SD 保存**: 「写真を SD に保存」が ON **かつ** SD が使えるときだけ `/ToolCheck/photos/YYYYMMDD-hhmmss.jpg` に書く (同じ秒の 2 枚目は `-2`)。時刻未設定なら `00000000-<起動からの秒>.jpg`
- **SD の有無**: 検出ピンが無いので、アイドル時に一定間隔で確認 (待機 5 秒 / 減光・消灯 30 秒)。書込失敗で「SD なし」に落として再マウントを待つ。
  **SD が無いあいだ設定の表示は自動で OFF (SD なし)**。設定自体は覚えておき、刺し直せば保存を再開する
  - **M3 の実測 (2026-09-13)**: 抜けている間の確認 (`exists` / 書込) は 1 回で約 3 秒、カードが無いときの `SD.begin()` は毎回 921ms 止まる。
    挿し直すと再マウントしなくても次の確認で戻った。→ **上の「待機 5 秒ごとに確認」をメインループで回すと、画面とタッチが定期的に止まる。**
    確認は別タスクに出すか、SD が無いと分かったら間隔を大きく空ける (M5 で決める)
- **電源を入れてから初めて PC からシリアルポートを開くと、本体が再起動する** (`rst:0x17`、M2〜M3 で 3 回観測)。SD が無いときに RAM だけに持つ無登録の写真は、
  保守で PC を繋いだ時点で消える。赤帯の記録 (`alerts`) は NVS にあるので残る。M5 で「再起動しても困らないか」と、開き方で避けられるかを見る
  → **2026-09-15: 困らない。対処しない** (M5 までに 4 回観測)
- **100 件を超えたら古い順に削除**: **アイドル時** (セッション無し・引き出し閉・10 秒無操作) に名前順で新しい 100 件を残す。0 バイトのファイルも消す
- **無登録の写真を表示し続ける**: 打ち切りで「無登録開放」「利用者不明の持出」になった開放の写真を、SD 保存の有無に関係なく一覧上部に出す。設定画面で確認して消すまで残る
- **履歴から写真を見る**: 開閉ログの各開放に写真名を記録する。貸出中・返却履歴は持出時と返却時の写真名を直接持つ (開閉ログが 200 件で回っても辿れる)。📷 の行をタップで全画面。SD に無いときは「写真はありません」

### 省電力 (`power_manager` / `power_hw`)

**起動時に切って、以後使わないもの**: ESP32-C6 の電源 (0x44 bit0 を Low) / USB-A の 5V (`setExtOutput(false, ext_USB)`) /
マイク・IMU (`cfg.internal_mic = false` / `cfg.internal_imu = false`) / システム LED / RS485 / カメラを使わない設定ならカメラの電源

| 状態 | 入る条件 | CPU | 画面 | QR ユニット | ToF 測定間隔 | カメラ | スピーカー |
|---|---|---|---|---|---|---|---|
| 操作中 | セッション・警告・設定・検索・写真表示・撮影・SD 書込 | 360MHz | 通常 (警告中は最大) | 連続 | 50ms | 開放直後だけ取り込み | 有効 |
| 待機 | 操作が終わってから減光まで | 360MHz (※) | 通常 | 連続 | 100ms | 停止 | 有効 (※2) |
| 減光 | 無操作 N 分 (既定 5 分) | 360MHz (※) | 減光 | **間欠** | 200ms | 停止 | 有効 (※2) |
| 消灯 | 無操作 M 分 (既定 15 分) | 360MHz (※) | **バックライト 0 だけ** (パネルスリープ中はタッチが効かないので、パネルは起こしたまま。2026-09-13 決定。ライトスリープは不採用) | 間欠 | 200ms | 停止 | 有効 (※2) |

- ※2 スピーカーは当初の案では待機以下で止めるとしていたが、**止めない (2026-09-15)**。入切のたびに始めるときの音が出るおそれがあり、M2 の実測で差は約 0.01A
- 復帰: 開放 / QR 読取 / タッチ → **先に 360MHz に上げてから**処理する。減光・消灯中の最初のタッチは復帰だけ
- 一覧の経過時間 (1 分ごと) は変わった行だけ 40MHz のまま描く。消灯中は描かない
- **未確認の無登録があるあいだは消灯せず減光で止める** (見せることが目的なので、そのぶんの電力は払う)。検証で問題なければ採用
- ~~**消灯中は手動ライトスリープ**~~ **不採用 (2026-09-12 M2: `esp_light_sleep_start()` の後、画面は真っ黒のまま QR にも USB にも反応せず、本体ごと止まった)**。以下は当初の案: 200ms ごとのタイマ復帰で QR (と ToF) だけ見て、また眠る。
  **M2 の検証で、復帰後に DSI・PSRAM・I2C・SPI・USB シリアルが正常で、電流が実際に下がれば採用**。
  採用後も `cfg` のフラグで入切できるようにし、現場で不具合が出たら切れるようにする。スリープ中は USB シリアルが切れるので、保守中は設定画面を開いて消灯させない
- **※ 2026-09-12 M2 の実測で変更: CPU を 40MHz / 20MHz に落とすと MIPI-DSI の送出が間に合わず (`E lcd.dsi: ... underrun happens`) `rst:0x7 (HP_SYS_HP_WDT_RESET)` で再起動した。画面を点けている間 (減光中も) は 360MHz 固定。** 電力は明るさ (消灯はバックライト 0)・QR の間欠・使わない電源 (C6 など) の遮断で稼ぐ。消灯中に DSI の送出を止めて落とせるかは未検証
- 測り方: USB 電力チェッカー (INA226 は USB 給電だけだと 0mA のままで使えなかった)
- **実測 (2026-09-13、USB 4.91V)**: 基準 (明るさ 60%・C6 ON・QR 自動) 0.57A / C6 OFF で −0.12A / 明るさ 60 → 15% で −0.08A、15 → 0 でさらに −0.08A /
  パネルスリープ −0.02A / QR 手動 −0.03〜0.12A / スピーカー停止 −0.01A / 一番絞って 0.25A (約 1.2W)。USB-A の 5V OFF は差なし (詳細は `spikes/README.md`)
- **統合ファームの実測 (2026-09-16、カメラは使わない設定)**: 操作中 0.49A (明るさ 60%) / 減光 0.35A (明るさ 5%) / 消灯 0.26A (明るさ 0%)。USB 4.91〜4.96V

### 永続化 (NVS)
- `partitions.csv` で **NVS パーティション `tooldb` 1MB** を追加 (既定 nvs 20KB では足りない。
  見積もり: 貸出 78 バイト ≒ 5 エントリ × 100 + 返却 134 バイト ≒ 7 エントリ × 100 + 開閉ログ 200 件 ≒ 2,000〜2,500 エントリ。
  実測で 32 バイトの blob が 1 件 3 エントリ、`tooldb` は 32,256 エントリ)
- 名前空間: `loans` (**キー = 物品番号**、値 = 利用者 ID・持出時刻・持出時の写真名・貸し出した順・印) /
  `hist` (リング 100、借りた人・返した人・持出と返却の時刻と写真名・印 [代理・返却者不明・返却漏れ・取消]) /
  `openlog` (リング 200、写真名付き) / `alerts` (赤帯 = 打ち切りの無登録開放・利用者不明の持出を、設定画面で確認するまで残す。**20 件、溢れたら古い方を消して消えた数を数える** — 2026-09-13 決定) /
  `cfg` (版数付き。版上げは移行を書く)。`loans` / `hist` / `openlog` / `alerts` の 1 件も先頭に版数を持つ (`core/loan_book` / `core/open_log`)
- **赤帯が付くセッションの電源断**: ①赤帯 ②赤帯の管理情報 ③溢れた最古の赤帯のキー削除 ④開閉ログ の順 (見せることが目的なので赤帯が先。④の前で落ちたら開閉ログの 1 件が欠ける)。
  ②の前で落ちた赤帯は読み込みで通し番号から数に入れる。③を消せなければ一覧から外し、次の変更の直前に消す (新しい赤帯を書くのは止めない)。
  当初は「開閉ログ → 赤帯、欠けた赤帯を開閉ログから補う」としていたが、RingStore が 1 件ごとの通し番号を出さないので 2026-09-13 に順序を入れ替えた
- 一時停止の残り時間は保存しない (再起動で警告は有効に戻る)
- **電源断の整合**: 貸出を閉じる操作 (返却・付け替え・取消) は ①返却履歴のスロット ②履歴の管理情報 (head) ③`loans` のキー削除 の順
  (付け替えは③で同じキーに新しい貸出を上書きする)。起動時は書かずに、最新の返却履歴が閉じた貸出を一覧から外し、残ったキーは次の変更の直前に消す。
  ③の前で落ちた付け替えの新しい貸出は失われる (もう一度読ませてもらう)。残ったキーを消せないうちは次の変更を書かない
- 起動直後に NVS へ書かない。**開けないときに自動で消さない** (「記録領域を読めません」画面 → NVS データ削除へ誘導)

### データ削除 (NVS・SD の写真)
- **SD の写真の全削除** (2026-09-14): `/ToolCheck/photos` の中のファイルだけを SD タスクで消す (ほかのフォルダには触らない)。終わったら開閉ログに「SD の写真を全部削除」を 1 件書く。
  記録の写真名は残るので、その行の写真は「写真はありません」になる。直近に撮った 1 枚は撮影タスクの RAM に残る (再起動で消える)
- **記録の削除** (`loans` / `hist` / `openlog`、`cfg` は残す) / **全削除** (`tooldb` ごと消去 → 再起動)。SD の写真は消さない
- 二段確認 (件数表示 → 3 秒長押し)。記録の削除後は開閉ログの 1 件目に「記録削除」
- USB シリアル `nvs erase records|all YES` は PIN を忘れたときの復旧経路を兼ねる。画面から PIN 無しで消せるのは「記録領域を読めません」画面の全削除だけ

### 時刻
- RTC に UTC で保持し、表示は設定の時差。年が 2026 未満 / 電圧低下フラグ → 赤帯「時刻未設定」、経過は「--」、写真名は `00000000-...`
- **上限は設けない (2026-09-13 決定「いつまで使うかわからない」)。** 未設定の RTC が返す 2048 年のような値も有効な時刻として扱う。
  **初回の時刻設定は利用者にしてもらう** (設置・操作メモに書く)。電源が抜けて時刻が狂ったときに電圧低下フラグが立つかは、M3 の残りで確かめる
- 設定: 設定画面の「時刻」/ USB シリアル `time set 2026-09-12T10:00`

## 利用シーンと対応

| シーン | 対応 |
|---|---|
| 返却に来た | 物品 QR を読むとその場で返却 (名札は要らない。返した人は記録しない) |
| まとめて返す | 物品 QR を続けて読み、「返却完了」ですぐ終える |
| QR を読んだが持って行くのをやめた | 「取りやめ」|
| 「貸出中」の物が引き出しにあり、別の人が持って行く | 「持出に切替」で付け替え |
| 名札を先にかざす / 自分の借り物を確かめたい | 名札先の 20 秒 (「完了」ですぐ次の人へ) / 閉じたまま名札で一覧 |
| 中を見ただけ | 名札だけで確定 → 開放ログに ID |
| 登録せず立ち去った | 警告 → 打ち切り → 持出は「不明」、写真を出し続ける、赤帯 |
| 次の人が無登録に気付く | 一覧上部の写真 / 開けた瞬間のオーバーレイの写真 |
| 過去に誰が開けたか | 開閉ログ・返却履歴の 📷 (SD の 100 件の範囲) |
| 撮影できない現場 | カメラを使わない設定 |
| Unit ToF を付けない現場 | 引き出しセンサを使わない設定。物品と名札の QR だけで記録し、名札で確定したときに撮影 |
| 写真を消したい (保管期間が過ぎた・現場から求められた) | データ削除の「SD の写真を全部消す」(開閉ログに残る) |
| モバイルバッテリーで置く | 使わない電源を切り、待機 → 減光 → 消灯 |
| 既にある管理番号のまま管理 / 置き場に無い | 2〜15 文字なら QR にしてそのまま / 検索 |
| 補充・棚卸し | 警告の一時停止 |
| 移設・向きの変更 | ToF 校正 / テスト撮影 |
| 保守で記録を取り出す / 運用開始 | USB シリアル出力 / 控えを取って記録の削除 |
| 不調 / 停電 | ヘッダの ● と機器情報 / NVS から復元 |

## リスク

1. ~~カメラが Arduino + M5Unified の構成で Tab5 上で動くか未確認~~ → **2026-09-13 M3 で go**。M5Unified の内部 I2C のハンドル (`i2c_master_get_bus_handle`) を
   `ESPVideoCamConfigClass::begin(bus)` に渡し、CSI は LDO を初期化しない (`ESPVideoCSIConfigClass::begin(cam, true)`) で 720x1280 を撮れた。
   **ただし M5GFX は内部 I2C を LL で直接叩くので、カメラが取り込んでいる間に `M5.update()` などで内部 I2C を使うと SCCB が失敗する** (IPA のゲイン設定が落ちる)
   → 取り込み中は内部 I2C を使う処理 (タッチ・RTC・IO エキスパンダ・電源) を止める。回転は PPA (47ms)、JPEG はハードウェア (20ms)。
   色は IPA の AWB で紫がかる。手動 WB は ISP パイプラインコントローラを切らないと効かず、Arduino のビルド済みライブラリでは切れない → **許容**
2. **40MHz / 20MHz で動かない周辺機器がありうる** (USB-Serial/JTAG・DSI・SPI・I2C・カメラ再開)。切替え時のちらつきや I2C の取りこぼしも見る。 **→ M2 で確認: 画面 (DSI) が 40MHz で落ちる。360MHz 固定にした**
   **特に USB シリアルが 40MHz で落ちると、以後の検証手段を失う** → 周波数を落とす処理はシリアルコマンドで入切できるようにし、既定 OFF から始める
3. **P4 のネイティブ USB をシリアルで開くとダウンロードモードに落ちる恐れ** (別製品 Unit PoE-P4 での事例。Tab5 で同じとは限らない) → `tools/serial.ps1` で DTR/RTS を落として開く。落ちたら esptool で戻す
4. **モバイルバッテリーは消費が小さすぎると自動で切れる** → 実際に使う製品で消灯状態を半日。RTC はスーパーキャパだけなので交換にかけられる時間も測る
5. ~~パネルのスリープ中にタッチが効くか未確認~~ → **2026-09-13 実測: パネルスリープ中はタッチが取れない。バックライト 0 だけなら取れる (差は約 0.02A)。
   → 消灯はバックライト 0 だけにし、開放・QR 読取・タッチのどれでも起こせるようにする**
6. **ToF の視野角 25° が広い** (80cm 下で照射径 約 35cm)。最下段で差が出ない恐れ → 到着後に各段を実測。ダメなら前へ出す・フード / VL53L1X で ROI 4×4 (約 15°) / リードスイッチ。
   → 2026-09-15 に届いたのは VL53L1X の Unit ToF4M (視野 15〜27°) だったので、ROI を絞る手がそのまま使える (いまは既定の 16×16。取り付けて各段を測ってから決める)
   測定間隔 200ms での検知の遅れも見る
   → **2026-09-16 が工具箱に取り付けて試し、問題なし。** ROI は既定の 16×16 のまま。取り付け後の実機の値は基準 `tof_baseline_mm` 1442・開の閾値 `open_delta_mm` 210・閉 `close_delta_mm` 50
7. **顔が写る画像は個人情報。** 撮影の掲示・利用目的・保存期間を示す。無登録の写真を出し続けるのは「晒し」と受け取られうる → 導入先の合意を確認。SD の保管も運用で決める
   → 手元の運用では撮影しない設定 (`camera_enabled` 0・`save_photos_to_sd` 0) で使っている。撮影を使うなら設置先で掲示と合意を取る
8. 開放の瞬間に顔が写るとは限らない (しゃがむ・横から・逆光)。開放を検知してから取り込むので撮影は少し遅れる → 遅延・画角・露出を実機で決める
9. スピーカーの音量と明るさの下限 → 実測で範囲と既定値を決め直す。RTC の保持時間。USB シリアルの PC 未接続時のブロック
10. SD は書込中の電源断で壊れうる → マウントできなければ「SD エラー」を出して動作は続ける。`partitions.csv` は初回に確定し以後変えない
